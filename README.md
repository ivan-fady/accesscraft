# AccessCraft

متجر إلكتروني لعرض منتجات يدوية. يدعم حسابات العملاء والحرفيين، وعزل السلة
والمفضّلة والطلبات حسب الحساب، وإدارة الحرفي لمنتجاته وصوره. يستخدم Stripe
Checkout لقبول الدفع وتسجيل الطلب عبر webhook موثّق.

## التشغيل المحلي

المتطلبات: Node.js 20.9 أو أحدث وpnpm 12.

```powershell
npm exec --yes --package=pnpm@12.3.4 -- pnpm install
Copy-Item .env.example .env.local
npm exec --yes --package=pnpm@12.3.4 -- pnpm dev
```

من دون إعداد الخدمات، يعرض الموقع منتجات توضيحية فقط ويُعطّل الدفع. لا تعتبر
المعاينة متجرًا جاهزًا لاستقبال طلبات حقيقية.

## إعداد Supabase

1. أنشئ مشروعًا في Supabase.
2. نفّذ ملفات الترحيل بالترتيب:
   `supabase/migrations/20261107000000_create_marketplace.sql` من محرر SQL في
   Supabase، ثم
   `supabase/migrations/20261107010000_add_accounts_and_owned_data.sql` ثم
   `supabase/migrations/20261107020000_add_delivery_dispatch.sql` ثم
   `supabase/migrations/20261107030000_allow_legacy_product_artisan_id.sql` ثم
   `supabase/migrations/20261107040000_add_cash_on_delivery.sql` ثم
   `supabase/migrations/20261107050000_add_messages_and_earnings.sql`.
   تطوّر الترحيلات جدول المنتجات والملفات الشخصية القديمة أيضًا. يُحوّل
   `products.price` القديم من الدولار إلى السنتات، ويحتفظ بالمنتجات المنشورة
   فقط كمنشورة؛ المنتجات ذات الحالة الأخرى تصبح مسودات حتى تراجعها. إذا تعذّر
   تحويل سعر قديم أو كان غير موجب، يتوقف الترحيل برسالة واضحة بدل تخمين قيمته.
   المنتجات القديمة لا تُنسب تلقائيًا إلى حساب حرفي؛ عيّن `owner_id` يدويًا
   فقط بعد التحقق من مالك كل منتج. يجعل الترحيل الأخير عمود `artisan_id`
   القديم اختياريًا؛ يعتمد التطبيق على `owner_id` لربط المنتجات بحساب الحرفي.
3. أضف رابط المشروع ومفتاح النشر العام إلى `.env.local` في
   `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`.
4. اضبط إعدادات المصادقة والبريد في Supabase، وحدد عنوان الموقع المحلي وعنوان
   الإنتاج ضمن إعدادات URL المسموح بها. ينشئ التطبيق ملف الحساب والدور المختار
   تلقائيًا عند التسجيل. قد يحتاج المستخدم إلى تأكيد بريده قبل تسجيل الدخول.
5. أضف المنتجات الحقيقية إلى جدول `public.products`، أو أنشئها من حساب حرفي.
   خزّن السعر بالسنتات ورابط صورة عام. لا تنشر المنتجات التوضيحية قبل استبدال
   النصوص والصور.
6. أضف مفتاح الخدمة الخاص في `SUPABASE_SERVICE_ROLE_KEY`. هذا المفتاح سري
   ويُستخدم على الخادم فقط؛ لا تضع قبله `NEXT_PUBLIC_`.

يسمح إعداد قاعدة البيانات للزوار بقراءة المنتجات المنشورة والمتوفرة فقط.
يستطيع الحرفي إدارة المنتجات والصور التابعة لحسابه فقط. سجل الطلبات وعناوين
الشحن محمية بسياسات RLS، ولا يستطيع العميل قراءة سوى طلباته. يسجل الخادم الدفع
المؤكد، وتتحقق قاعدة البيانات من حساب العميل والمخزون عند طلب الدفع عند التوصيل.
يلزم تسجيل الدخول بحساب عميل للشراء. تحتفظ كل هوية
بحقيبتها ومفضّلتها في المتصفح على حدة.

بعد تسجيل الطلب (أو تأكيد الدفع للطلبات المدفوعة بالبطاقة) ينشأ طلب توصيل مرة
واحدة. يظهر الطلب لكل حساب توصيل مسجل، وتضمن قاعدة البيانات أن قبول الطلب ينجح لحساب واحد فقط؛ عندها يختفي من
قوائم بقية المندوبين ويظهر ضمن طلبات المندوب الذي قبله. تتحدث القائمة تلقائيًا
وتظهر حالة التوصيل للعميل في سجل طلباته. يستطيع المندوب المعيّن تحديد الطلب
كمكتمل. لا تُسند الطلبات التي تحتاج مراجعة مخزون إلى التوصيل.

تتيح صفحة الرسائل محادثات مرتبطة بطلب بين العميل والحرفي صاحب المنتج، وبين
العميل ومندوب التوصيل بعد إسناد الطلب إليه. تحفظ المحادثات والرسائل في Supabase
وتحميها سياسات RLS. تعرض صفحة أرباح الحرفي المبيعات المكتملة بعد خصم عمولة
منصة ثابتة قدرها 5%، وتعرض صفحة أرباح المندوب 5.50 دولار لكل توصيل مكتمل.
الدفع عند الاستلام لا يدخل في أرباح الحرفي إلا بعد تسجيل التوصيل كمكتمل؛ أما
طلبات البطاقة فتُحتسب بعد تأكيد الدفع. هذه تقارير تقديرية وليست نظام تحويل
أموال أو صرف مستحقات.

## إعداد Stripe

1. أنشئ حساب Stripe واستخدم مفاتيح الاختبار أولًا.
2. أضف المفتاح السري في `STRIPE_SECRET_KEY`.
3. أنشئ webhook على
   `https://YOUR_DOMAIN/api/webhooks/stripe` للأحداث
   `checkout.session.completed` و
   `checkout.session.async_payment_succeeded`.
4. أضف مفتاح توقيع webhook في `STRIPE_WEBHOOK_SECRET`.
5. اجعل `NEXT_PUBLIC_SITE_URL` عنوان الموقع النهائي، مع `https://` في الإنتاج.

يدعم المتجر الدفع عند التوصيل دون إعداد Stripe، كما يدعم البطاقات عبر Stripe
بالدولار الأمريكي. رسوم التوصيل الثابتة 5.50 دولار؛ جمع عنوان البطاقة عبر Stripe
متاح للولايات المتحدة وكندا. الضرائب غير محسوبة تلقائيًا. اضبط الضرائب والشحن
والاسترجاع ومتطلبات حماية المستهلك قبل تفعيل الدفع الحقيقي.

## الفحص والنشر

```powershell
npm exec --yes --package=pnpm@12.3.4 -- pnpm typecheck
npm exec --yes --package=pnpm@12.3.4 -- pnpm build
```

يمكن نشر التطبيق على Vercel أو أي استضافة تدعم Node.js. أضف جميع المتغيرات
الموجودة في `.env.example` ضمن إعدادات الأسرار في منصة الاستضافة، ثم اربط Stripe
بدومين الإنتاج. لا ترفع `.env.local` أو مفاتيح الإنتاج إلى Git.

سجل الطلبات الفعلي متاح للعملاء، وإدارة المنتجات والصور متاحة للحرفيين.
تدفق التوصيل يوزع الطلب بين المندوبين، لكنه لا يوفر توجيهًا جغرافيًا أو إثبات
تسليم أو صرفًا فعليًا للأرباح.

## ما يلزم قبل إطلاق سوق متعدد البائعين

اختبر تسجيل الحسابات وتأكيد البريد ورفع الصور وسياسات RLS والدفع وwebhook
وتنافس حسابي توصيل على الطلب نفسه باستخدام مفاتيح Stripe الاختبارية أولًا.
لا تُفعّل الدفع الحقيقي قبل إعداد الضرائب والشحن والاسترجاع ومتطلبات حماية
المستهلك. يلزم بناء حساب أجر المندوب وتدفق الاسترجاع قبل تشغيل سوق متعدد
البائعين.
